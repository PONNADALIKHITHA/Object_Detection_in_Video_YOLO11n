## 3. Problem Statement

Object detection in video involves identifying objects continuously across successive video frames. This project implements a video object-detection application using the pre-trained YOLO11n model. A recorded video is read frame by frame, YOLO11n performs inference on each frame, and the detected objects are visualized with bounding boxes, class labels and confidence scores.

## 4. Objective

- Understand the use of a pre-trained object-detection model.
- Load YOLO11n correctly.
- Process a video as a sequence of frames.
- Perform inference continuously on the frames.
- Process detection results.
- Display bounding boxes, labels and confidence scores.
- Save the processed video.
- Demonstrate the system using at least three different video inputs.

## 5. Introduction to the Pre-trained Model

YOLO means **You Only Look Once**. It is an object-detection model family that predicts object locations and classes from visual input.

This project uses **YOLO11n**, the assigned pre-trained detection model. The model is used for inference rather than being trained from scratch.

Official model documentation:
https://docs.ultralytics.com/models/yolo11

## 6. Why This Model Was Selected

YOLO11n is the model assigned to Project 32 in the college project-allocation document. It is suitable for continuous video inference because it can accept individual frames and return object detections that can be visualized and written back to a video.

## 7. Model Architecture / Working Principle

At a high level, the YOLO11 detection configuration contains a backbone for extracting visual features and a detection head for producing object detections at multiple scales.

The official YOLO11n configuration includes components such as:
- Convolution layers
- C3k2 blocks
- SPPF
- C2PSA
- Multi-scale feature connections
- Detect head

For this project, the important inference pipeline is:

**Input Video → Frame → YOLO11n → Inference → Bounding Boxes / Class Labels / Confidence Scores → Annotated Frame → Output Video**

## 14. Model Inference

## 19. Limitations

- Detection depends on the visual quality of the input video.
- Very small, blurred, or heavily occluded objects may be difficult to detect.
- Poor lighting can affect detection.
- Processing speed depends on available CPU/GPU hardware.
- The general pre-trained model is limited to the object classes it was trained to recognize.
